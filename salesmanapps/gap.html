The short version

The first demo was built from a summarised brief rather than from the actual requirement document. That brief named six modules, deferred ten of them to a "phase two" roadmap, and introduced an AI assistant layer that appears nowhere in the requirement.

The result was a well-finished demo of the wrong system. The parts that were built worked properly — but they answered a question that had not been asked, and left seven required modules at zero.

Root causes

1
An AI layer nobody asked for

Four AI features were built and made the centrepiece: route scoring, coaching nudges, a morning briefing and price anomaly detection. The requirement document contains no mention of AI at any point. A large share of the build went into something that was never requested — and it made the demo look like it was solving a different problem.

2
The three transaction models were absent

Consignment, Bil to Bil and Cash are the heart of the system, and the requirement gives them its longest section. Consignment in particular is a different business flow, not a setting: deliver 100 units, return next month, count 30 on the shelf, bill only the 70 that sold. The first demo had a single generic order flow and none of this.

3
Jadual Harian was built as the thing the spec ruled out

The requirement is explicit about what this screen is not:

❌ Bukan attendance   ❌ Bukan tracking visit   ❌ Tidak perlu Pending / Completed

The first demo built check-in with GPS tagging, timestamps and planned/visited statuses — precisely the pattern that was excluded. What was wanted was a simple ordered list of shops with Navigate, WhatsApp and Profile shortcuts.

4
The primary user was inverted

The layout is a salesman app — sixteen mobile screens, with the dashboard as the salesman's home screen after login. The first demo led with a manager desktop dashboard and treated the salesman view as a secondary panel.

5
Core modules were labelled "phase two"

DO, SO, Product & Stock, Return, Running Number and Refer & Earn were presented on a "coming in the full build" strip. In the requirement these are modules 05, 06, 10, 11, 14 and 16 — core, not optional. That strip was meant to read as honesty; it read as "your system was not built."

6
The Customer Profile was not a command center

The requirement states the core concept plainly: Customer Profile = Command Center, one screen from which every action and every history for an outlet is reachable. The first demo had a read-only manager report with no actions on it.

What was removed

The AI layer is gone

All four AI features have been taken out. They were not in the requirement, they consumed build effort that belonged to the missing modules, and they distracted from what the system is actually for.

If an AI layer is wanted later — suggested visit order, collection prioritisation, order-pattern alerts — it is a separate conversation with its own scope, on top of a system that first does what was asked.
